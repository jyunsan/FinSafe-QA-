# 【v1.0】提示词工程

## 1. 设计目标

FinSafe-QA V1.0 的提示词工程目标是让大模型在受控边界内完成自然语言理解。

系统采用：

```text
自然语言问题
↓
大模型解析结构化意图 JSON
↓
系统基于白名单 Schema 和模板生成 SQL
↓
执行 SQL
↓
系统模板生成自然语言结果说明
↓
可信层输出 SQL、数据血统、置信度和审计信息
```

该设计的核心原则是：

- 大模型负责理解自然语言，不直接自由拼接 SQL。
- SQL 生成由系统基于白名单表、字段和模板完成。
- 所有结果必须来自数据库查询结果，不允许模型编造数值。
- 复杂归因、开放式判断不作为 V1.0 核心承诺。

## 2. 数据库 Schema 上下文

提示词中会显式提供数据库可用表、字段和字段含义，让模型知道业务指标和真实字段之间的关系。

```text
可用数据库为 SQLite，本系统只允许查询以下表和字段：

表 companies：
- stock_code：股票代码
- short_name：公司简称
- industry：行业

表 financial_metrics：
- stock_code：股票代码，关联 companies.stock_code
- report_date：报告日期，如 2025-09-30
- report_period：标准报告期，如 2025Q3、2024A
- revenue：营业总收入，单位百万元
- net_profit：净利润，单位百万元
- rd_expense：研发费用，单位百万元
- operating_cash_flow：经营活动现金流净额，单位百万元
- gross_margin：销售毛利率，单位 %
- total_assets：资产合计，单位百万元
- total_liabilities：负债合计，单位百万元
- accounts_receivable：应收账款，单位百万元
- inventory：存货，单位百万元
- data_provider：数据来源
- source_url：公开数据源 URL
- snapshot_version：数据快照版本
```

## 3. 意图识别提示词

### 3.1 使用位置

代码位置：`src/prompts.py` 中的 `INTENT_SYSTEM_PROMPT`。

该提示词用于把用户问题解析成结构化意图，而不是直接生成 SQL。

### 3.2 Prompt

```text
你是 FinSafe-QA 的金融问数意图识别助手。

你的任务不是直接回答问题，也不是生成 SQL，而是把用户的自然语言问题解析为结构化 JSON。

[注入数据库 Schema 上下文]

支持的公司简称：
药明康德、凯莱英、泰格医药、昭衍新药、百克生物、迪安诊断、康龙化成、美迪西、贝达药业、神州细胞

支持的指标：
营业总收入、净利润、研发费用、经营活动现金流净额、销售毛利率、资产负债率

支持的操作类型：
- single_metric：单公司单指标查询
- top_n：某指标 TopN 排名
- average：某指标均值
- industry_average：行业均值，目前主要用于资产负债率
- negative_filter：筛选负数指标，目前主要用于经营活动现金流净额
- list_metric：列表查询

报告期规范：
- “2025年第三季度”“2025Q3”“2025年三季度”统一为 2025Q3
- “2024年”“2024全年”“2024年全年”统一为 2024A
- 未明确时间时默认 2025Q3

输出要求：
1. 只输出 JSON，不要输出 Markdown。
2. 不要编造不在白名单中的公司、指标或字段。
3. 不确定时将 confidence 降低，并在 clarification_needed 写明原因。
4. JSON 字段必须包含：
   operation, company, metric, period, top_n, confidence, clarification_needed
```

### 3.3 示例

用户问题：

```text
药明康德2025年第三季度营业总收入是多少？
```

期望输出：

```json
{
  "operation": "single_metric",
  "company": "药明康德",
  "metric": "营业总收入",
  "period": "2025Q3",
  "top_n": null,
  "confidence": 0.92,
  "clarification_needed": ""
}
```

## 4. SQL 生成策略

V1.0 不让大模型直接生成 SQL，而是采用“意图 JSON + SQL 模板”的方式。

原因：

- 避免模型编造表名和字段名。
- 避免生成危险 SQL。
- 便于做字段白名单校验。
- 便于记录数据血统和 SQL 回放。

示例：

```text
意图 JSON：
{
  "operation": "top_n",
  "metric": "营业总收入",
  "period": "2025Q3",
  "top_n": 3
}

系统生成 SQL：
SELECT c.stock_code, c.short_name, f.revenue AS value, ? AS currency_unit
FROM financial_metrics f
JOIN companies c ON c.stock_code = f.stock_code
WHERE f.report_period = ? AND f.revenue IS NOT NULL
ORDER BY value DESC
LIMIT ?
```

## 5. 结果生成策略

V1.0 的结果回答不交给大模型自由生成，而是由系统根据 SQL 查询结果模板化生成。

这样做的原因是：

- 金融问数结果必须严格来自数据库。
- 模板化回答更容易保证数值、单位和报告期不被改写。
- 本地评测时更加稳定可控。

示例：

```text
药明康德在2025Q3的营业总收入为 32857.0 百万元。
```

## 6. 可信校验提示词

### 6.1 使用位置

代码位置：`src/prompts.py` 中的 `TRUST_REVIEW_PROMPT`。

该提示词用于后续扩展可信层复核，目前 V1.0 的可信分数主要由规则计算。

### 6.2 Prompt

```text
你是 FinSafe-QA 的可信校验助手。

请基于意图 JSON、SQL、结果行数和数据血统，判断本次回答的可信度。

只输出 JSON：
{
  "risk_level": "low|medium|high",
  "reasons": ["原因1", "原因2"],
  "suggestion": "给用户展示的简短提示"
}

校验重点：
- 公司、指标、报告期是否完整
- SQL 是否只使用白名单表和字段
- 查询结果是否为空
- 是否存在模糊指标，如“利润”“增长质量”
- 是否涉及超出结构化问数范围的问题
```

## 7. 运行配置

项目通过 `.env` 读取硅基流动配置：

```text
SILICONFLOW_API_KEY=你的 API Key
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1
SILICONFLOW_MODEL=Qwen/Qwen2.5-7B-Instruct
```

其中 `SILICONFLOW_MODEL` 可选。若未配置，系统默认使用 `Qwen/Qwen2.5-7B-Instruct`。
