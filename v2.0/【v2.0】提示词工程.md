# 【v2.0】提示词工程

## 1. 设计目标

FinSafe-QA V2.0 的提示词工程目标是让大模型在可信边界内辅助完成：

- 分析意图识别。
- 分析计划生成。
- 图表类型推荐。
- 结论表达约束。
- 可视化配置校验。

V2.0 延续 V1.0 的核心原则：

> 大模型负责理解与表达，结构化计算由 SQL 和规则层完成。

因此，V2.0 不允许大模型直接编造 SQL 结果、财务数值、行业研报内容或投资建议。

---

## 2. 提示词分层

V2.0 提示词分为三层：

| 层级 | 对应模块 | 作用 |
| --- | --- | --- |
| 分析意图层 | `ANALYSIS_INTENT_SYSTEM_PROMPT` | 将自然语言问题解析为结构化分析 JSON |
| 洞察生成层 | `INSIGHT_SYSTEM_PROMPT` | 基于结果表和计算字段生成克制分析结论 |
| 图表校验层 | `CHART_REVIEW_PROMPT` | 判断图表类型、字段映射和单位是否合理 |

当前默认使用规则解析，只有显式设置 `FINSAFE_USE_LLM=1` 时才调用大模型。这样可以保证本地评测稳定可复现，同时保留接入 SiliconFlow OpenAI-compatible 接口的能力。

---

## 3. 分析意图识别提示词

### 3.1 任务定义

分析意图识别提示词要求模型不直接回答问题，而是输出结构化 JSON。

核心约束：

- 不生成 SQL。
- 不生成自然语言结论。
- 不编造不在白名单中的公司、指标或字段。
- 缺少字段或外部信息时，必须写入 `limitations`。

---

### 3.2 可用 Schema 注入

提示词中显式注入数据库可用表和字段：

```text
表 companies：
- stock_code：股票代码
- short_name：公司简称
- industry：行业

表 financial_metrics：
- revenue：营业总收入，单位百万元
- net_profit：净利润，单位百万元
- rd_expense：研发费用，单位百万元
- operating_cash_flow：经营活动现金流净额，单位百万元
- gross_margin：销售毛利率，单位 %
- total_assets：资产合计，单位百万元
- total_liabilities：负债合计，单位百万元
- accounts_receivable：应收账款，单位百万元
- inventory：存货，单位百万元
```

这样可以降低字段幻觉，例如用户问“短期借款”“货币资金”“扣非净利润”时，模型应识别为当前库不支持，而不是自行假设字段存在。

---

### 3.3 支持的分析类型

```text
- single_metric：单公司单指标查询
- trend：单公司或多公司多期趋势
- top_n：某指标 TopN 排名
- compare：多公司同指标对比
- average：指标均值
- positive_filter：多指标均为正筛选
- ratio_analysis：占比或效率计算
- growth_analysis：同比/环比增长率
- anomaly_detection：波动最大或异常识别
- driver_analysis：基于结构化数据的有限归因
- validation：数据一致性校验
- unsupported：超出当前结构化数据范围
```

这些类型对应 V2.0 引擎中的规则分支，避免让模型输出不可执行的自由分析路径。

---

### 3.4 输出 JSON 规范

```json
{
  "analysis_type": "compare",
  "companies": ["凯莱英", "药明康德", "泰格医药"],
  "metrics": ["销售毛利率"],
  "period": "2025Q3",
  "periods": [],
  "top_n": null,
  "chart_type": "bar",
  "confidence": 0.9,
  "limitations": []
}
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| analysis_type | 标准分析类型 |
| companies | 识别到的公司列表 |
| metrics | 指标列表 |
| period | 单一报告期 |
| periods | 趋势分析中的多报告期 |
| top_n | 排名数量 |
| chart_type | 推荐图表类型 |
| confidence | 意图解析置信度 |
| limitations | 缺失字段、缺失公司或外部数据限制 |

## 4. 洞察生成提示词

### 4.1 任务定义

洞察生成层只允许基于系统提供的结果表、计算字段和图表配置生成结论。

提示词核心规则：

```text
1. 先给结论，再给数据依据。
2. 每个关键判断必须绑定公司、报告期、指标、数值或变化率。
3. 明确区分“事实”和“推测”。
4. 不提供投资建议。
5. 当数据缺失、口径不一致或样本过少时，必须提示限制。
```

---

### 4.2 结论约束策略

V2.0 不允许以下输出：

| 禁止项 | 原因 |
| --- | --- |
| 无数据支撑的经营归因 | 结构化财务数据不足以解释所有经营原因 |
| 投资建议 | 存在金融合规风险 |
| 编造行业研报观点 | 当前数据源不包含研报全文 |
| 编造业务量、价格、海外收入 | 当前字段不覆盖这些信息 |
| 把 2025Q3 与年度数据当成严格同比 | 周期口径不同 |

示例：

```text
不推荐：百克生物收入增长主要来自某产品放量。

推荐：百克生物收入变化可以从公开财务指标中观察，但当前结构化数据不包含产品销量和价格信息，不能确认具体驱动因素。
```

## 5. 图表校验提示词

### 5.1 任务定义

图表校验层用于判断图表是否适合当前问题。

校验重点：

- 趋势问题是否使用时间轴。
- 排名和对比问题是否使用柱状图或横向柱状图。
- 单位是否完整。
- 图表维度是否与结果表字段匹配。
- 2025Q3 与年度数据混合比较时是否提示周期口径差异。

---

### 5.2 图表选择规则

| 分析目标 | 推荐图表 | 原因 |
| --- | --- | --- |
| 时间趋势 | 折线图 | 突出时间序列变化 |
| 公司排名 | 柱状图 | 便于比较大小 |
| 多公司同指标对比 | 柱状图 | 强调横向差异 |
| 资产负债结构 | 柱状图 | 展示资产、负债、权益三项规模 |
| 多指标关系 | 散点图/组合图 | 适合表达关系，但当前版本优先表格或柱状图 |
| 不适合图表的问题 | 表格 | 保留数据与边界说明 |

---

## 6. 边界与兜底策略

V2.0 的边界识别是提示词工程的重要组成部分。

当问题包含以下信息时，系统进入 `partial_or_unsupported` 或 `unsupported`：

| 类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 未覆盖公司 | 迈普医学、百诚医药 | 返回数据覆盖限制 |
| 未覆盖字段 | 短期借款、货币资金、扣非净利润 | 返回当前可用字段，不编造结果 |
| 外部研报信息 | 行业研报、TIDES 业务贡献 | 只返回结构化财务指标，提示需要 RAG |
| 政策与宏观判断 | 集采政策、地缘政治影响 | 不输出持续时间或投资判断 |
| 严格同比/环比缺失基期 | 2025Q3 对比 2024Q3、2025Q2 | 提示数据缓存缺少对应报告期 |

---

## 7. 与 V1.0 的差异

| 维度 | V1.0 | V2.0 |
| --- | --- | --- |
| 核心目标 | 可信问数 | 可信分析与可视化 |
| 意图输出 | 查询操作 JSON | 分析计划 JSON |
| 结果生成 | 模板化自然语言回答 | 结论 + 数据依据 + 风险提示 |
| 可信层 | SQL、血统、置信度 | SQL、分析计划、图表配置、血统、置信度 |
| 评测重点 | 准确性、系统性、可回溯性 | 增加分析质量、可视化质量、边界识别 |

---

## 8. 当前实现说明

当前 V2.0 工程中：

- `src/prompts.py` 保存提示词模板。
- `src/engine.py` 默认走规则解析，保证评测稳定。
- `FINSAFE_USE_LLM=1` 时可启用大模型意图识别。
- SQL 仍由系统规则生成，不由大模型直接生成。
- 分析结论和图表配置均基于 SQL 结果和规则计算生成。

这种设计的核心原则是：模型辅助理解，系统负责验证，结果必须可追溯。
